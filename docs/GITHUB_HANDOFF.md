## Commit-message guidelines

Write commit messages as a human engineer would for a real, professional
open-source project. Use a short, present-tense, conventional-commit-style
subject line, optionally followed by a body explaining *why*, not a
decorative or promotional description of *what a great feature this is*.

**Good examples:**
- `docs: finalize project documentation`
- `feat: integrate analyst console`
- `feat: add execution timeline and reporting`
- `chore: prepare repository for public release`
- `fix: correct grounding overlay color mapping`
- `test: add regression coverage for confidence method labeling`

**Explicitly forbidden in any commit message, anywhere in this
repository's history:**
- The words "Claude" or "Anthropic" in any form.
- Any "generated by AI" / "AI-assisted" / "co-authored by an AI"
  wording or trailers.
- Session IDs, session URLs, or any reference to an AI assistant's
  internal tooling, sandbox, or development environment.
- Decorative or filler commit messages (e.g. "update stuff", "final
  final version", "wip", emoji-only messages).
- Exaggerated or marketing-style claims (e.g. "revolutionary AI
  breakthrough", "state-of-the-art", "production-grade") that are not
  literally true of what the commit changes — this project's own
  documentation is deliberately honest about what is a classical-CV
  baseline versus a real model, and commit messages must not
  contradict that.
